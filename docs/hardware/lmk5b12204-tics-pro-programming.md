# LMK5B12204 TICS Pro 烧录指南

本文说明如何用 TI 的 TICS Pro 生成 LMK5B12204 的配置，以及如何把这份配置写进片内寄存器和 EEPROM。寄存器级的时序全部取自数据手册第 9.5 节与《LMK5B12204 Register Maps》（SNAU256），这部分是权威且不随软件版本变化的；TICS Pro 的菜单名称随版本有差异，以实际界面为准。

---

## 摘要

**一、TICS Pro 本身不能直接烧你这块板。** 它的通信通道是 USB2ANY（EVM 上是板载 MCU 跑的等效固件）。本项目没有 EVM，要么外接一个 USB2ANY 适配器到 J13，要么让 TICS Pro 只负责算频率、导出寄存器表，由板上的 U8（STM32F103CBTx）发 I2C 完成实际写入。**推荐后者**——不用买硬件，也不用改板。

**二、烧录 EEPROM 的核心只有四条寄存器写。** 依次是 `R157 = 40h`（把活动寄存器提交到 SRAM）、`R164 = EAh`（解锁）、`R157 = 03h`（擦除并烧写）、然后等约 230 ms。其中**第二、三条必须紧邻，中间不能插入任何其他寄存器事务**，否则擦写命令根本不会执行。

**三、写寄存器时有三个字节必须跳过。** R12、R157、R164 带掩码，R353~R435 是 TI 内部测试寄存器，一律不要碰。把导出的寄存器表原封不动地从 R0 刷到 R435，是最容易踩的坑。

**四、本板有两处需要留意：J13 没有 GND 引脚，GPIO1 没有上下拉。** 前者影响外接适配器时的地线，后者影响上电时采样到的 I2C 从机地址。详见第 6 节。

## 1. 硬件通路：配置怎么进到芯片里

@fig:tics_hwpath 图 1　三条把配置送进 LMK5B12204 的通路

TICS Pro 是一个 EVM GUI 框架，它和器件之间的物理通道只有一条：USB2ANY。EVM 上那颗"板载 MCU"跑的就是 USB2ANY 固件，所以在 GUI 看来两者没有区别。理解这一点，三条通路的差别就清楚了：

**通路 ①（TI 官方 EVM）** 是手册和 EVM 用户指南默认的做法。本项目没有 EVM，此路仅作参照。

**通路 ②（外接 USB2ANY 接 J13）** 让 TICS Pro 真正在线操作你的芯片：GUI 里改一个参数就立刻写进器件，调试体验最好。J13 是 1×6 排针座，引脚定义为 SDA / SCL / PDN / GPIO0 / GPIO1 / GPIO2，I2C 和复位控制都齐了。两个前提：**U8 的 PB10/PB11 必须配置成高阻输入**（否则两个主机抢总线），**地线要另外从 TP2 引过来**（J13 上没有 GND 脚）。

**通路 ③（U8 STM32 代劳）** 是本项目推荐的做法。TICS Pro 退化成一个纯粹的"频率规划计算器"：算完配置，导出 R0~Rn 的十六进制表，把这张表编进 STM32 固件，由 STM32 通过板内 I2C 写进 U1。不用买适配器、不用改板、不用担心总线争用，缺点是每改一次配置要重新编译烧录 MCU 固件。

## 2. TICS Pro 操作流程

@fig:tics_gui 图 2　从安装到导出配置的八步

几处容易卡住的地方：

**器件列表里找不到 LMK5B12204。** TICS Pro 支持 `Select Device → Import User Device`，导入 TI 提供的器件 zip 包即可。较老的版本可能完全不支持这颗芯片，需要升级——EEPROM/SRAM 映射的生成能力也是在较新版本里才补齐的，如果 EEPROM 页没有导出选项，先确认版本。

**Simulation 模式。** 没接硬件时 GUI 仍可正常使用，所有计算和导出功能都在，只是写不进器件。通路 ③ 全程就工作在这个模式下。

**AutoUpdate 选项。** 打开时，界面上任何改动会立刻写进器件；关闭时改动只留在 GUI 里，需要显式 `Write All`。在线调试时建议先关掉，改完一组参数再整体写入，避免中间态让 PLL 反复失锁。

**导出的两种数据不是一回事。** `Export Hex Register Values` 导出的是**活动寄存器**表（R0~Rn），用于运行时配置；EEPROM 页的 `Export GUI Map` 导出的是 **SRAM/EEPROM 映射**（第 0~252 字节），只有走第 4 节的"方法 #2 直接写 SRAM"时才用得上。绝大多数情况下，你需要的是前者。

## 3. 把配置写进活动寄存器

@fig:tics_regmap 图 3　寄存器写入范围、掩码与收尾动作

手册 9.5.5 节给出的通用主机编程序列：

1. 上电，PDN 已拉高，器件进入 I2C 模式
2. 从低地址到高地址依次写 R0 ~ R352，**跳过掩码位**
3. 向 R12[7] 写 1，进入软复位（寄存器值不会被清掉）
4. 向 R12[7] 写 0，退出软复位，器件开始 PLL 启动序列
5. 如需开机自启动，再按第 4 节烧 EEPROM

掩码的含义是"这些位保持原值，不要用导出表里的值覆盖"：

| 地址 | 掩码 | 为什么 |
|------|------|--------|
| R12 | A7h | 器件复位/控制寄存器，软复位要在第 3、4 步单独操作 |
| R157 | FFh | NVM 控制位，整字节跳过——EEPROM 命令必须按第 4 节的时序单独发 |
| R164 | FFh | NVM 解锁位，同上 |
| R353 ~ R435 | FFh | TI 内部测试/诊断寄存器，一律不要写 |

R157 尤其要注意：它同时含 REGCOMMIT、NVMERASE、NVMPROG 三个自清位。如果批量写寄存器时把它一起刷了，轻则什么都不发生，重则在你没打算烧录的时候触发一次擦写，白白消耗 100 次配额里的一次。

**这一步写完，配置就已经生效了。** 掉电会丢，但足以完成全部功能验证。建议**先在这个状态下把四路输出、PLL 锁定、相噪抖动全部测完**，确认配置无误再考虑烧 EEPROM。

## 4. 烧录 EEPROM

@fig:tics_eeprom 图 4　EEPROM 烧录的寄存器级操作顺序

EEPROM 不能直接写，它是从片内 SRAM 阵列整片烧过去的。所以烧录分两段：先把配置送进 SRAM，再发擦写命令。送进 SRAM 有两种方法。

### 4.1 方法 #1：寄存器提交（推荐）

前提是活动寄存器已按第 3 节配置好。然后只需一条写：

```
R157 ← 40h        # REGCOMMIT，把当前寄存器内容提交到 SRAM，该位自动清零
```

优点是不需要知道 SRAM/EEPROM 映射长什么样，导出一份寄存器表就够了。缺点是提交的内容就是器件当前的工作配置，没法在不打断运行的前提下烧另一份配置。

### 4.2 方法 #2：直接写 SRAM

绕过活动寄存器，器件继续正常输出时钟的同时把另一份配置写进 SRAM：

```
R159 ← SRAM 地址高 5 位
R160 ← SRAM 地址低 8 位
R162 ← 数据字节          # 同一次事务内连续写会自动地址递增
```

只需要写第 0~252 字节，**253~255 是 TI 保留字节，不得改写**。这条路径需要 EEPROM 页导出的 SRAM/EEPROM 映射文件。

用户可编程字段也在这一步顺带写入：字节 5 是 I2C 从机地址高 5 位（默认 C8h，对应 7 位地址 0x64），字节 11 是 EEPROM 镜像版本号 EEREV，字节 249~252 是四个备用字节，可以写产品序列号之类的追溯信息。这几个字节只能用方法 #2 写。

### 4.3 发擦写命令

两种方法殊途同归，SRAM 准备好之后：

```
R164 ← EAh        # NVMUNLK 解锁码
R157 ← 03h        # NVMERASE + NVMPROG，整片擦除并烧写
                  # 等待约 230 ms，轮询 R157[2] NVMBUSY 直到读回 0
R164 ← 00h        # 重新上锁（可选，防误烧）
```

**`R164 ← EAh` 和 `R157 ← 03h` 必须是紧邻的两次寄存器事务。** 手册原文是"Steps 1 and 2 must be atomic writes without any other register transactions in-between"。中间只要插进去任何一次读或写——包括一次状态轮询、一次调试打印触发的寄存器读——解锁就失效，擦写命令被静默忽略，而且没有任何报错。这是这套流程里最隐蔽的失败点。

擦除 115 ms、编程 115 ms，合计约 230 ms。**这段时间内绝对不能断电**，否则 EEPROM 内容不完整，下次上电 CRC 校验失败。

### 4.4 校验

烧录完成后必须**断电重上电或硬复位**，然后读两个寄存器：

| 寄存器 | 期望值 | 含义 |
|--------|--------|------|
| R156 NVMCNT | 比烧录前 +1 | 累计烧录次数，上限 100 次 |
| R157[5] NVMCRCERR | 0 | 为 1 表示 EEPROM 数据 CRC 不匹配，配置无效 |
| R11 EEREV | 你写入的版本号 | 仅方法 #2 写过时有意义 |

NVMCNT 出厂就是非零的（工厂预编程消耗了若干次），所以**第一次上电就该把它读出来记下**，之后每烧一次核对一次增量。100 次配额没有任何办法恢复。

CRC 机制值得解释一下：烧录时器件自动算一个 CRC 存进 EEPROM（NVMSCRC，R155）；每次上电从 EEPROM 读回数据时再实时算一遍（NVMLCRC，R158）。两者不匹配就置 NVMCRCERR，并且**在寄存器加载后就停住，不继续 PLL 锁定流程**。所以一块烧坏了 EEPROM 的板子表现是"没有任何输出"，而不是"输出频率不对"。

## 5. 用 U8 STM32 完成烧录

通路 ③ 的完整顺序，以及和第 3、4 节的对应关系：

```
1. STM32 上电，先把 PB15(PDN) 驱动为低，PB13(GPIO1) 驱动为低
2. 等待 OCXO 预热稳定（见《LMK5B12204 配置指南》第 4 节）
3. PB15 拉高，U1 开始 POR，采样 HW_SW_CTRL=0 与 GPIO1=0
4. I2C 从机地址 = 0x64，按第 3 节写 R0 ~ R352（跳过 R12/R157/R164）
5. R12[7] 写 1 再写 0，触发 PLL 启动
6. 读状态寄存器确认 APLL 已锁定、无 LOL
7. —— 以上是每次上电都做的事，到此为止就能正常工作 ——
8. 只在需要固化配置时：R157←40h，R164←EAh，R157←03h，轮询 NVMBUSY
9. 复位后读 NVMCNT 与 NVMCRCERR 校验
```

第 8 步应当做成一条**需要显式触发的调试命令**（通过 J16 的串口发一条指令，或按住某个条件上电），绝不能放在正常启动流程里。否则每次上电烧一次，100 次配额一周就没了。

I2C 写事务本身是标准的：从机地址 0x64（7 位）+ 16 位寄存器地址 + 数据字节。第 4.3 节那两条相邻写，在 STM32 固件里要写成两次独立的 `HAL_I2C_Mem_Write`，中间不插任何别的 I2C 操作——不要在中间加日志打印，如果打印函数里有读寄存器的动作就会破坏原子性。

## 6. 本板需要留意的两处

**J13 没有 GND 引脚。** 六个脚全是信号：SDA / SCL / PDN / GPIO0 / GPIO1 / GPIO2。外接 USB2ANY 时必须另外从 TP2（GND 测试环）或安装孔引一根地线过去，否则 I2C 电平没有共同参考，通信会时好时坏。如果以后改版，建议把 J13 扩成 1×8，补上 GND 和 3.3 V。

**GPIO1 没有上下拉，I2C 地址取决于 POR 时刻 STM32 的引脚状态。** GPIO1（U1 引脚 24）是三电平输入，在 POR 时刻采样，决定 7 位从机地址的低两位：低 = 0x64、悬空 = 0x65、高 = 0x66。本板 GPIO1 只接到 U8 的 PB13 和 J13.5，没有任何电阻。STM32 复位后 GPIO 默认是浮空输入，此时 U1 会采样到"悬空"，地址变成 0x65。

按第 5 节的顺序做就没有问题：**STM32 先把 PB13 驱动为低，再拉低 PDN，然后拉高 PDN 触发一次新的 POR**，此时采样到的是确定的低电平，地址固定为 0x64。如果嫌这样绕，在 GPIO1 上加一个 10 kΩ 下拉电阻即可一劳永逸。

顺带说明 PDN 的行为：PDN 内部有上拉，STM32 复位期间它是高的，U1 会先自行启动一次——这不要紧，STM32 起来后把 PDN 拉低再拉高，会重新触发完整的 POR 序列，HW_SW_CTRL 和 GPIO1 都会被重新采样。

## 7. 常见失败与对应现象

| 现象 | 可能原因 |
|------|---------|
| I2C 完全无应答 | 地址不是 0x64（见第 6 节 GPIO1）；或 PDN 仍为低，串口未激活 |
| 寄存器能写，输出全无 | 出厂默认四路输出全部 Disabled，配置里没显式使能 |
| 寄存器写完 PLL 不锁 | OCXO 尚未稳定就开始 VCO 校准；用 PDN 推迟启动 |
| 发了擦写命令但 NVMCNT 不增 | NVMUNLK 与擦写命令之间插入了其他寄存器事务 |
| 烧录后上电完全没输出 | NVMCRCERR = 1，EEPROM 数据无效；重新烧一次 |
| 烧录次数莫名增加 | 批量写寄存器时没有跳过 R157，误触发了擦写 |
| GUI 显示已连接但写不进去 | AutoUpdate 关闭且未执行 Program All Register |
